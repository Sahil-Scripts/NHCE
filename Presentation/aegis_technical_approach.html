Custom Algorithm — Stage-by-Stage
The closed-loop reasoning pipeline in full detail
Stage A
Initial Risk Normalization
Raw transaction features pass through XGBoost. Output is sigmoid-normalized to a probability prior P₀(fraud) ∈ [0,1] for each event entering the investigation loop.
r = sigmoid(XGBoost(x)) → [0,1]
↓
Stage B
Confidence Estimation via Entropy
Shannon entropy is computed over the current belief distribution. High entropy = high uncertainty → more evidence needed. Low entropy = confident belief → proceed to decision.
H(X) = -Σ p(x)·log₂ p(x) < θ → exit loop
↓
Stage C
Adaptive Evidence Selection
The Evidence Planner scores every available query source using information utility: expected information gain divided by query cost. Highest-utility source is queried next — maximally efficient investigation.
Utility = InfoGain(source) / QueryCost(source)
↓
Stage D
Temporal Pattern Matching
Graph data and transaction history are scanned for Δt anomalies: velocity bursts, dormant account reactivation, timed round-tripping and multi-hop circular flows within time windows.
flag if Δt < τ_burst ∨ pattern ∈ KnownRings
↓
Stage E
Block / Approve Decision
Once entropy falls below threshold, the converged posterior P(fraud|all evidence) is compared to the decision boundary θ. Above θ → BLOCK and generate STR. Below → APPROVE and log.
P(fraud|E) > θ → BLOCK · else → APPROVE

Why This Approach Wins
Technical differentiators
🧠
Adaptive by design: The entropy loop means AEGIS only gathers evidence until it is confident — never over-investigating, never under-investigating. Every query is chosen to maximise information gain per unit cost.
🕸️
Graph-native: Fraud rings, shell chains, and circular laundering are structurally invisible to row-based ledgers. AEGIS traverses entity graphs at arbitrary depth — no hop limit.
📋
Audit-ready output: Every evidence step, Bayesian update, and decision boundary is logged — producing a regulator-ready reasoning chain alongside the final STR report.
